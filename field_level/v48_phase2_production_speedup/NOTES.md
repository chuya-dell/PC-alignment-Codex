# v48 Phase 2 本番解析の高速化(結果を変えない範囲)

## 実装内容・旧版からの変更点

- 旧版 `field_level/v9_phase2_production_reanalysis/` は変更していない。v48 は v9 を読み込んで使う。
- `field_fast_kernels.py`: 結果を変えない高速版の2関数。
  - `fast_sample_grid_features`: `shared.theoretical_grid_evaluation.sample_grid_features` の、ピラー1本ごと(約8.6万回)の Python ループを、配列演算に置き換えた。7×7 の範囲と中央 3×3 の足し算を、元と同じ順序(行優先)で行う。
  - `fast_estimate_phase_origin_fft` / `fast_lattice_from_fft`: `shared.lattice_indexing.estimate_phase_origin_fft` が全画素(約420万)に2次元の複素指数関数を2回かけて足していたものを、軸ごとの1次元の複素指数関数の積(分離形)に置き換えた。数学的に同じ式。浮動小数点の丸めの違いは出うるが、今回の検証では出力は一致した。
- `field_run_phase2_production_parallel.py`: v9 の `process_pair_cached`(視野対ごとの結果ファイル `.npz` を作る関数)を、プロセスの並列で全視野対に先に実行する。そのあと、v9 の `main()` を変更せずに呼び、統計表を作る。視野対どうしは独立なので、並列化で結果は変わらない(OpenCV のスレッド数は1にして、各プロセスが競合しないようにする)。
- `field_verify_speedup.py`: 4通りの実行(逐次・元の関数 / 逐次・高速版 / 並列・元の関数 / 並列・高速版)の結果と時間を比べる検証用。

### 実行(v9 と同じ引数に、--workers と --kernels を足したもの)

```powershell
python field_level/v48_phase2_production_speedup/field_run_phase2_production_parallel.py --pair-manifest <対の一覧.csv> --cache-dir <キャッシュ> --out-dir <出力> --workers 8
```

`--kernels original` にすると、元の関数のまま並列だけを使う。

## 結果概要と保存先

**土台のコードは2通りで検証した。** (A)現在の標準構成の位置合わせ(v15 の適応的な空間範囲つき特徴点照合+サブピクセル精緻化)を含む `origin/refinement/outlier-artifact-mask-20260927`(`c6be781`、v10〜v24 を含む)。この版 v48 は (A) の上に置いた。(B)`origin/main`(`ceb764d`)。`origin/main` は v10〜v24 を含まず、`shared/registration.py` が古い(Phase 2 の位置合わせ)。両方で同じ結論(出力のビット一致、4〜5倍の高速化)になった。以下の表は (B)、(A) の数値はその下。

測定条件:ThinkPad(LENOVO 82Y7、Intel Core i7-13700H、14コア・20スレッド、メモリ約13.7ギガバイト)、Windows 11、Python 3.13、numpy 2.3.3、scipy 1.16.2。画像は 260824_p50_SHC6OH の生画像(2044×2048)を Googleドライブの同期フォルダから読んだ。ベースは v9 のコミット(`origin/main` の `ceb764d`)。

## 既知の問題・未解決事項

- 手元(ThinkPad)の v9 逐次の実測は 1対 約3.2秒で、409対なら約22分になる。「1600枚で約5時間」(ボイスメモ)とは桁が合わない。5時間の対象の経路・機械・読み込み元が、この版では特定できていない。共用のデルデスクトップで同じ測定を行う必要がある(未実施)。
- 検証は 260824_p50_SHC6OH の一部の対(最大40対)に限る。全409対と、位置合わせが失敗(品質管理で棄却)する対を多く含む場合の一致は未確認。
- 並列実行の速度は機械(コア数・メモリ・Googleドライブの読み込み速度)に依存する。
- `lattice_from_fft` の元の関数は、`fft2` と `maximum_filter` の部分(約0.5秒)を残している。結果の一致を保てる範囲では、これ以上の短縮は未検討。
- 位置合わせ(約0.65秒)は、アルゴリズムを変えると結果が変わりうるため、この版では触っていない。
