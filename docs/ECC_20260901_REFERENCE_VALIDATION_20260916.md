# 2026-09-01記録を基準にした3段アフィンECC検証 — 2026-09-16

## 結論

判定は **再現用として使用不可**。位置1〜5、7、8の7視野について、Phase 2の
生16-bit→0..1正規化とアフィンECCを再利用し、0.25→0.5→1.0の3段ピラミッドを
ゼロ並進から実行した。2026-09-01の記録との完全一致は **0/7視野** で、事前提案した
「7視野中6視野以上が全指標で一致」の基準を満たさなかった。

そのため、Position 6に対する0.125開始・多開始点の救済探索は実行していない。
別の目的関数・変換の座標規約を当時の記録と同一視できない状態で救済探索をすると、
結果を「深い初期化の効果」と解釈できないためである。

## 実装と固定した条件

- 実装: `field_level/v4_ecc_reference_validation/field_validate_ecc_against_20260901.py`
- 再利用: Phase 2の `image_for_ecc`, `run_ecc_path`, `affine_metrics`。
- 入力: 260826 p50 SAM Sample 1のpre/post。確定済みピッチ `a=7.286 px` は変更・再推定していない。
- 前処理: ネイティブ16-bit強度を`float32`の0..1へ線形正規化。高域強調、欠陥マスク、傷マスクは使わない。
- 変換: OpenCV `MOTION_AFFINE`（並進・回転・等方/異方スケール・剪断を許容）。
- ピラミッド: 0.25→0.5→1.0。前段の変換を次段初期値へ拡大して渡す。
- 各段の打切り: 最大100反復、EPS=1e-6。実行環境の1コマンド時間制限のため、7視野は同一条件で個別実行後に集約した。

## 解釈

今回の結果は「アフィン+3段ピラミッド」という大枠だけでは当時の数値列を復元できないことを示す。
最も可能性が高い未固定要素は、(1) ECC入力画像の前処理・評価領域・マスク、(2) 変換行列の向きと
回転中心を含む並進報告規約、(3) 相関値の計算方法、(4) 各段の収束条件と初期値、である。
この結果からFOV 1-6だけを局所解と判断したり、除外基準を変えたりはできない。
