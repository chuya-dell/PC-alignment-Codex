# Position 6 画像そのものの直接調査 — 2026-09-16

指示役からの依頼: 位置合わせ方式(ECC・ORB/RANSAC)がそれぞれ異なる変換(並進・回転)で
Position 6だけにつまずくことが判明したため、位置合わせの計算方法ではなく**Position 6の
実画像そのもの**を直接調べ、原因が(a)物理的欠陥、(b)蒸着・基板作製工程、(c)撮影条件、
(d)原因不明のいずれかを判断する。

## 結論

**(b) 基板作製工程(パターン露光フィールドの境界)に起因する系統的なもの、と判断する。**
Position 6・7の視野には、他視野より桁違いに明るい(一部飽和する)交差する直線状の
構造がある。この構造は**2026-08-26と2026-08-28という別日程・別基板でほぼ同じ画素位置に
再現した**ため、特定チップの偶発的なゴミ・キズではなく、ステージの視野グリッドが
基板パターンの書き込みフィールド境界と交差する位置にPosition 6・7が固定的に
対応していることによる系統的な現象と判断する。2026-08-26の基板製作時QCログには
Sample 1(基盤1)のPosition 6を欠陥として記録した行はなく、(a)「目視で分かる
ゴミ・キズとして認識された欠陥」が主因とは言えない。この構造は通常のゴミ・シミの
目視チェックでは境界線として認識されにくく、ピクセル強度の統計を見て初めて
顕在化するものと考えられる。

## 5. 総合判断と対策案

**判定: (b) 蒸着・基板作製工程(パターン書き込みフィールド境界)に起因する系統的なもの。**
(a)目視で識別済みの物理的欠陥(ゴミ・キズ)ではない（QCログに記載なし、また日程を
またいだ再現性は偶発的ゴミでは説明できない）。(c)撮影条件(ピント・照明)にも
明確な悪化はない(Laplacian分散・Tenengradはむしろ良好)。したがって(d)原因不明とはせず、
(b)と判断する。

Position 6のECC局所解トラップ(大きな並進で破綻)、Position 7側でのORB/RANSAC回転誤差
（[`AXIS_ROBUSTNESS_VERIFICATION_20260916.md`](AXIS_ROBUSTNESS_VERIFICATION_20260916.md)の
Position 6検証も同じ境界を含む視野で行われている）は、いずれもこの高輝度な直線構造で
説明が付く。ECCは強い輝度勾配を持つ支配的な領域に相関最適化が引きずられやすく、
大きな並進探索時にこの直線同士を誤って重ねる局所解に落ちる可能性がある。ORB/RANSACは
直線上に類似した特徴点が多数並ぶため、回転時に対応点が線に沿ってずれる
（開口問題に類似）ことで並進推定に数px級のバイアスが生じ得る。いずれも本レポートでは
検証しておらず、あくまで整合的な説明としての位置づけに留める。

### 対策案

1. **該当領域のマスク化（推奨）**: 交差線の画素位置は視野内でほぼ固定
   (縦線: x≈16–130、横線: y≈1780–1936、260826 Position 6の場合)であり、既存の
   `pillar_level/v1_human_approved_pixel_masks/` の人手承認マスク運用に乗せて、
   Position 6・7のこの帯状領域だけを解析から除外する。視野全体を除外するより
   有効視野を多く残せる。
2. **視野単位の自動QCフラグ**: 55000 DN以上の画素数(または同等の飽和指標)を
   撮影直後に計算し、閾値(例: 5000画素)を超えたら人手確認に回す運用を追加する。
   目視QCでは見落とされていたが、この指標なら260826・260828のどちらも即座に
   検出できていた。
3. **ステージ視野グリッドの見直し(長期)**: 可能であれば、視野グリッドの原点・
   間隔を基板のパターン書き込みフィールド境界からずらし、Position 6・7が
   境界をまたがないようにする。基板設計・撮影計画側の変更が必要なため、
   本依頼の範囲を超える。
4. 位置合わせアルゴリズムの変更・比較は今回の対象外(既存の検証で十分)だが、
   1のマスク化を先に行った上でECC/ORB双方を再評価すれば、Position 6の
   registration失敗がこの領域由来かどうかを直接確認できる。これは
   「現行標準を警報役として並走させる仕組み」等の次の依頼で検討する。
