# マスク適用ベンチマークの評価方法検証、およびPhase 1/Phase 2の役割分担 — 2026-09-16

指示役からの依頼: [`docs/MASKED_ALIGNMENT_FINAL_DECISION_20260916.md`](MASKED_ALIGNMENT_FINAL_DECISION_20260916.md)
で報告した「マスク適用後のORB/RANSACはPosition 6で全シナリオ回収率100%」という結果について、
(1) 評価方法(スパイク配置・スコアリング)が結果を作っていないかの確認、(2) Phase 1/Phase 2の
役割分担と本番解析経路の切り分け、の2点を確認する。

## 結論(要約)

1. **回収率100%は評価方法のアーティファクトではない。** マスク領域内にも人工スパイクは
   通常通り配置されており(回避していない)、元の実装ではマスク領域内のスパイクを
   評価対象から除外していたが、除外せず全スパイクを評価しても回収率は99.0〜100.0%を
   維持した(最大でも1ポイントの低下)。
2. **これまでの濃度依存性解析はPhase 1のみを通っており、Phase 2は一切使われていない。**
   Phase 1(`align_and_match_dataframes`、溝検出+ICP)は現在も唯一の本番経路であり、
   Phase 2(`register_image_pair_affine`)は今回の検証群のためだけに新設した経路で、
   生産コードからの呼び出しはまだ無い。さらに、**Phase 1自身の溝検出がPosition 6で
   物理的にあり得ない値(縦方向84.8px)を返す**ことが今回の追加確認で判明した。
   Phase 1がPosition 6で何らかの問題を抱えている可能性があり、これは今回のPhase 2の
   検証では一切カバーされていなかった。本番解析へPhase 2の知見を反映するには、
   単純な呼び出し口の差し替え以上の作業が必要である。

## 1. 回収率100%が測定方法によるものでないかの確認

### スパイク配置ロジック

`field_run_masked_benchmark.py`の`sample_truth(shape, n, rng)`は、画像全体
(余白60px除く)から一様乱数でスパイク座標を選ぶ。**マスク領域(x≈16–130, y≈1780–1936)を
避ける処理は無い。** つまりマスク領域内にも通常通りスパイクは配置される。

Position 6でスパイク数20/50/100の3試行を行った場合、マスク領域(画像全体の2.49%)内に
落ちたスパイク数は以下の通り(乱数シードは既存ベンチマークと同一)。

| スパイク数 | マスク内スパイク数 |
| --- | ---: |
| 20 | 0 |
| 50 | 2 |
| 100 | 3 |

### 評価ロジックの当初の仕様

`detect_and_score`の当初実装は、`score_mask`(=`bright_band_mask`)を使って
**マスク領域内の正解スパイクを評価対象(分母)から除外**していた
(`eval_truth = truth[~score_mask[...]]`)。つまりマスク領域内のスパイクが
検出されなかった場合、それは「回収失敗」としてカウントされず、**評価対象外として
黙って除外される仕様だった。** これは指示役が懸念した通りの構造であり、
回収率100%という結果の一部が、この除外によって嵩上げされている可能性があった。

### 検証: マスク領域内スパイクも含めた実質回収率

`field_run_masked_benchmark.py`と同一のシード・変換・登録結果(マスク適用ORB/RANSAC、
ECC双方)を再利用し、除外なしで**画像全体の全スパイクを評価**するスコアリングを追加実装した
(`field_verify_masked_scoring.py`)。位置合わせ自体(マスクを使って相関/特徴点探索から
明部帯を除外する処理)は変更していない。変更したのは採点対象の範囲のみ。

| 方式 | マスク | シナリオ | 除外あり回収率(元の報告値) | 除外なし回収率(全スパイク評価) |
| --- | --- | --- | ---: | ---: |
| ORB/RANSAC | あり | 並進(realrange) | 100.0% | **100.0%** |
| ORB/RANSAC | あり | 縦(ty) | 100.0% | **99.0%** |
| ORB/RANSAC | あり | 回転(theta) | 100.0% | **99.0%** |
| ORB/RANSAC | あり | 拡大縮小(scale) | 100.0% | **99.0%** |
| ECC | あり | 並進(realrange) | 26.2% | 26.0%(参考。悪いことに変わりはない) |

詳細: `data/results/v7_masked_alignment_benchmark/masked_scoring_verification_summary.csv`,
`masked_scoring_verification_position6.csv`

**除外を無くしても、ORB/RANSAC(マスク適用)の回収率は99.0〜100.0%を維持した。**
最大の低下幅は1ポイント(スパイク数100中1本程度)で、除外の有無は結論
(「マスク適用ORB/RANSACはPosition 6で安定して高い回収率」)を変えない。これは、
マスクが影響するのは**位置合わせの推定**(相関計算・特徴点探索の入力からの除外)のみで、
推定された変換行列自体は画像全体(マスク領域を含む)に適用され、評価されるためである。
マスク領域内のスパイクも、正しく推定された変換があれば通常通り検出される。

**この検証結果を踏まえ、`field_run_masked_benchmark.py`本体のスコアリングも
「除外あり」から「除外なし(画像全体を評価)」へ変更した**（後述、コミット済み）。
今後この方式で再実行した場合、`method_summary_*.csv`の数値は上表の「除外なし」列に
準じたものになる(結論・標準方式の選定は変わらない)。

## 2. Phase 1とPhase 2の役割分担、本番解析経路の切り分け

### 用途・入出力の違い

| | Phase 1 (`align_and_match_dataframes`) | Phase 2 (`register_image_pair_affine`) |
| --- | --- | --- |
| 目的 | 検出済みピラー座標同士の位置合わせ | 生画像同士のグローバルなアフィン推定 |
| 入力 | pre/postのピラー座標データフレーム(pillar_id, x, y)+ 溝検出用の生画像 | pre/post生画像そのもの |
| 手法 | 溝検出による粗いシフト → 2次ICPによる点群フィッティング → 8x8タイル局所補正 | ECC相関最大化 または ORB特徴点+RANSACの単一グローバルアフィン(いずれもマスク対応) |
| 出力 | 変換後座標 + 変換辞書(粗シフト・回転・2次ICP・局所補正)+ post側との対応点マッチング | 1つの2×3アフィン行列 |
| 局所非剛体補正 | あり(8x8タイル局所補正) | なし(グローバルアフィンのみ) |

Phase 1はピラー検出後の**座標レベル**の位置合わせで、対応点マッチング(post画像への
射影・輝度サンプリング)まで一貫して担う。Phase 2は今回の半合成ベンチマーク
(field_level/v5–v7)のために新設した**画像レベル**のアフィン推定のみで、局所補正機構を
持たない。

### これまでの濃度依存性解析が通っている経路

以下のコード検索で確認した(全て`shared.registration.align_and_match_dataframes`を
直接呼んでいる)。

- `field_level/source_snapshot_260908_p50_crossday_ledger_audit/field_run_crossday_direct_sampling.py`
  (260826・260827・260828の日程横断比較)
- `field_level/source_snapshot_260910_crossday_direct_grid/field_crossday_direct_sampling.py`
- `field_level/v1_pixel_mask_count_comparison/field_pixel_mask_count_comparison.py`
  (承認済みマスクの有効数比較、目標濃度vsブランク検定の前段)
- `pillar_level/v1_human_approved_pixel_masks/pillar_prepare_defect_review.py`

**これまでのSAM・DNA検出の濃度依存性解析は全てPhase 1のみを通っている。
Phase 2を呼んでいる箇所は本リポジトリ中に`field_level/v7_masked_alignment_benchmark`
(今回の検証自体)以外に存在しない。** 第3の経路は無い。

### 重要な追加確認: Phase 1自身がPosition 6で問題を抱えている可能性

今回の一連の検証(半合成ベンチマーク、軸別頑健性確認、画像フォレンジクス、マスク適用)は
**すべてPhase 2(ECC・ORB/RANSAC)を対象にしたもので、Phase 1は一度も検証していなかった。**
指示役の依頼を機に、Phase 1の中核である溝検出(`detect_grooves`)をPosition 1・6の
pre/postに対して直接実行したところ、以下の結果を得た。

| Position | 溝検出による粗シフト dx (px) | 粗シフト dy (px) | 対応点マッチ率 |
| --- | ---: | ---: | ---: |
| 1 | 14.38 | −0.47 | 85.14% (70963/83353) |
| **6** | 15.09 | **84.78** | **75.86%** (60964/80357) |

Position 6のdy=84.78pxは、2026-09-01記録再構成検証([`ECC_20260901_REFERENCE_VALIDATION_20260916.md`](ECC_20260901_REFERENCE_VALIDATION_20260916.md))
で他視野について観測された実データの縦シフト範囲(約−8.1〜+20.2px)から大きく外れており、
物理的に妥当とは考えにくい。ICPによる微調整後の最終並進も`[15.04, 84.79]`とほぼ変わらず、
**溝検出の粗シフトがほぼそのまま採用されている。** また対応点マッチ率もPosition 1の
85.1%に対しPosition 6は75.9%と明確に低い。`converged=True`は返るが、これはICPの
反復最適化が収束したことを示すのみで、結果が物理的に正しいことは保証しない。

`detect_grooves`は画像左端付近(x帯[0,300]内、探索範囲x∈[30,270])の縦方向溝と、
上端付近(y帯[0,300]内、探索範囲y∈[30,270])の横方向溝を、明るさプロファイルの
極小値として検出する設計になっている。この縦溝の探索帯は、Position 6・7で見つけた
明部帯の縦線(x≈16–130)と重なるため、**Phase 1の粗シフトが今回発見した明部帯の
影響を受けている可能性がある。** ただし横溝の探索帯(y∈[0,300])は、明部帯の横線
(y≈1780–1936)とは重ならないため、dy=84.78の異常の直接原因を明部帯だけで説明する
ことはできない。他の視野(Position 2の単独`detect_grooves`テストでもdy=−157.6pxと
同様に大きな値が出た)を踏まえると、**溝検出器自体が特定条件下で不安定な可能性もあり、
Position 6固有の問題と、溝検出器全般の頑健性の問題が混在している可能性がある。**

この観察は今回の依頼(経路の切り分け)に付随して見つかったものであり、原因の特定や
Phase 1の修正は本依頼の範囲外とする。**ただし、「Phase 2側は対策済みだが本番で
使われているPhase 1側は未検証」という状態を放置すべきではない**ため、次の依頼として
明示的に扱うことを推奨する。

### 本番解析へ反映するために必要なこと(見積もり)

Phase 2(マスク適用ORB/RANSAC)の知見を本番の濃度依存性解析へ反映するには、
少なくとも以下が必要である。

1. **Phase 1自体のPosition 6問題の検証**（上記の新規発見を受けて、優先度を上げるべき）。
   溝検出が明部帯や周期構造にどう反応するかを、Position 1〜8・複数日程で体系的に確認する。
2. **入出力の型の違いの解消**。Phase 1は「ピラー座標データフレーム→座標変換+対応点
   マッチング」、Phase 2は「生画像→単一アフィン行列」であり、直接の置き換えはできない。
   実現方法は大きく2通り:
   - (a) Phase 2のアフィン行列を、Phase 1の「溝検出による粗シフト」の代替(コースシフトの
     置き換え)として使い、その後段のICP・局所補正はPhase 1のまま残す。溝検出よりも
     ロバストな初期値を与えられる可能性があるが、ICP・局所補正との整合性を別途検証する
     必要がある。
   - (b) Phase 1全体をPhase 2に置き換える。ただしPhase 2は局所非剛体補正を持たないため、
     [`P50_RADIAL_PITCH_DISTORTION_REPORT_20260915.md`](P50_RADIAL_PITCH_DISTORTION_REPORT_20260915.md)
     で否定された放射歪み以外の局所非理想性(あれば)を補正できなくなるリスクがある。
   - いずれの方式でも、Phase 2のマスク(`bright_band_mask`)をPhase 1側(溝検出・ICP対応点
     マッチング)にも適用できるよう拡張する必要がある。
3. 上記を踏まえた、Phase 1適用済みの過去の濃度依存性解析結果(260826・260827・260828等)の
   **再検証要否の判断**。Position 6がこれらの解析で実際にどの程度悪影響を与えていたかは
   未評価。

これらは本依頼の範囲(経路の切り分けの明確化)を超えるため、実施はしていない。
